## Blocages / Risques
- **Réseau non garanti** : `npm install` (build TS), commandes Atlas/Docker peuvent échouer hors ligne → acceptance partielle à signaler.
- **`mk/react.mk` + `docker/react.dockerfile` manquants** : bloquent le build du dashboard (T-008/T-009).
- **Base unifiée vs 99.9 %** : point de couplage assumé (cf. MEMORY D11) ; scindable par schéma plus tard.
- **T-006 dette schéma identity** : `migrations/0001_identity.sql` est minimal vs les entités domaine de l'Identity Service. Colonnes absentes : `workspaces.slug/owner_id/plan`, `users.name/role`, `api_keys.name/prefix/permissions/last_used_at/expires_at`. Le service compile et les use cases sont complets, mais en l'état la persistance Drizzle mappe des valeurs par défaut et `updateLastUsed` est un **no-op silencieux** (lastUsedAt jamais persisté), les permissions/expiration ne sont pas durables. **Tâche db-engineer à planifier** : migration `0010_identity_*.sql` ajoutant ces colonnes + retrait des défauts dans les repos, avant mise en production (validation API Key avec permissions/expiration réelles). Champs domaine RICHES conservés volontairement (logique métier portée par les entités).
- **T-006 `paths` tsconfig auth-api** : `@fleece/api-common` résolu via `baseUrl`+`paths` (béquille offline car node_modules non lié). esbuild résout par node_modules → risque de divergence build/type-check si le symlink workspace diffère du `paths`. À retirer ou aligner (alias esbuild) une fois `npm install` exécuté en CI. Non bloquant.
- **T-006 build TS non exécuté** : `make build pkg=auth-api` (esbuild) + `tsc` projet local non exécutés (offline, node_modules absent). `tsc --noEmit` validé via un tsc système hors projet uniquement. À re-valider en CI online.
- **T-005 dette schéma webhook** : `webhook_deliveries` (0006) ne stocke ni `payload` ni `next_retry_at`, et `webhook_endpoints` n'a pas de colonne `active`. Le service compile et passe les tests (Active=true par défaut, payload/scheduling en mémoire), mais un **scheduler de retry réel est bloqué** tant que la migration n'est pas alignée → tâche db-engineer à planifier avant le câblage du retry automatique. Guard `ErrEmptyPayload` en place pour éviter un redispatch silencieux d'un body vide.
